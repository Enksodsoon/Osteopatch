A documented path from a small change to verified software—and a separate, explicit path to deployment.

Pull request quality gates

CI checks both backends, both frontends, the scoped static-analysis rules, dependency records and the static website. Required jobs converge into a single quality-gate. Dependencies are locked, third-party Actions are commit-pinned and normal jobs use read-only repository permissions.

Large optional model and WSI environments are checked manually instead of being installed for every documentation change. Real-data browser tests remain separate because they require verified artifacts that do not belong in Git.

GitHub Pages: documentation only

The website build publishes six HTML pages, one stylesheet, three existing product screenshots and build metadata. It does not publish application secrets, runtime databases, model binaries or the image collection. Local links, fragments, image alternatives and safety disclosures are checked before publication.

The build metadata is deterministic and includes hashes of the frozen evaluation and generated files. It is not a clinical-validation certificate.

AWS: a separate approval boundary

The frontend deployment workflow is manual and restricted to the protected aws-demo environment. It remains disabled until its enable flag and an approved short-lived OIDC role are configured. It updates only the existing demo’s web assets; it does not create infrastructure, upload datasets or redeploy the API/model container.

Prepared does not mean deployed.

Missing or expired workshop credentials, an absent OIDC role or an unapproved environment prevent deployment. The source UI can be newer than the workshop demo. No zero-cost guarantee is made for AWS operations.

Opt-in MCP tooling

The repository includes Kiro profiles for read-only GitHub, public AWS documentation and a pinned local Playwright server, plus a VS Code example. Kiro servers are disabled by default and have no auto-approved tools. Tokens are supplied locally, never committed.

Installing a profile is not authentication or permission to run it. MCP servers can access privileged resources and are not a security sandbox. Enable only the server needed for the task.

Releases and responsibility

Release automation prepares a draft prerelease with explicit research limitations. A maintainer inspects the version, checks and artifacts before publishing. There is no automatic production certification, clinical use approval or background retraining.
