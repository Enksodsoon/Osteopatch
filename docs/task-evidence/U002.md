## 2. What changed

- **New** `src/styles/tokens.css` — the single source of truth: surfaces, text, lines,
  accents, `--focus`, warning/error, the three class accents, the 4/8/12/16/24/32 spacing
  scale, radii/elevation, and the type scale. Every colour is a literal opaque hex so a
  reviewer can compute WCAG contrast from the file itself.
- `src/styles.css` — imports that file first, **both** `:root` blocks deleted (values moved,
  not rewritten), 12 legacy custom properties renamed to the semantic contract
  (`--bg`→`--canvas`, `--panel`→`--surface`, `--ink`→`--text`, `--muted`→`--text-muted`,
  `--line`→`--border`, `--nt/--vt/--nec`→`--class-nt/-vt/-nec`, `--warn-ink`→`--warning`,
  `--warn-bg`→`--warning-surface`), hardcoded error/warning literals folded into tokens,
  the focus ring replaced, the reduced-motion block added, and the legacy layer's padding
  and gaps moved onto the spacing scale. **89 → 63 hex literals; 26 values consolidated.**
- **New** `src/test/design-tokens.test.tsx` — 28 tests covering the five named checks.

## 3. Defects found in the code this task touched

1. **Focus ring at 1.42:1.** `rgba(139,63,39,.22)` composites to `#e5d3cb` over the panel —
   effectively invisible. Now `var(--focus)` `#6b2c17`, measured **10.35:1** in a real browser.
   This was a live accessibility defect in shipped UI, not a theoretical one.
2. **No reduced-motion support at all.** An infinite shimmer and a hover lift ran regardless of
   the reader's preference. Added `prefers-reduced-motion: reduce`; verified in-browser that
   `animationName` goes `osteo-shimmer` → `none` and duration → `0s`.
3. **Duplicated `:root` made the theme a lie.** Anyone reading the top of the file saw
   `--nt: #3b7a57`; the app painted `#476f5d`. Removed.
4. **Stale cool-gray fallback** `var(--border, #d8dee4)` on one control. Dropped the fallback.

## 4. Defects found in my own work this task

1. **A wrong test, corrected before implementing.** I first asserted `height: 100vh` must go.
   That was **false reasoning**: browser zoom does not change CSS px, so `100vh` does not clip
   at 200%, and switching it to `min-height` would move scroll containment from the inner pane
   to the document — the behaviour redesign U002 explicitly forbids. Replaced with an honest
   `overflow: hidden` guard. `.app` was left untouched.
2. **`node:fs`/`node:url` could not type-check.** No `@types/node` exists in this workspace and
   `tsconfig.json` pins a `types` allowlist; both are outside this task's authorisation.
   Attempted first: Vite `?raw`, `?inline`, and `import.meta.glob` — **all three return a
   zero-length string** under this project's `css: false` vitest setting. Settled on a
   filesystem read behind two `@ts-expect-error` directives, deliberately not `@ts-ignore`:
   if `@types/node` is ever added the build fails loudly rather than the suppression rotting.
5. **Four of my own assertions were wrong** (five failing tests) and were corrected, not
   weakened — a token filter that matched `--text-body`/`--text-label` as colours; a focus regex
   anchored at `:focus-visible` that silently dropped the leading `button`; a missing
   class→token map; and a label matcher expecting `"NON TUMOR"` when the chip renders the
   literal `"NON_TUMOR"` (correcting it made the assertion stronger, not weaker).
6. **A `?raw` attempt made 24 tests fail against a *correct* implementation.** The stylesheet
   really was right (proved against the built bundle); the import form was the defect.
7. **Browser sweep measured the wrong property.** `element.focus()` does not trigger
   `:focus-visible` in Chromium, so the first sweep read the *text* colour (15.53:1) and looked
   like a pass on the wrong thing. Real `Tab` presses now drive it.

optional: hue is the redundant channel here. I deliberately did **not** repaint them; AT04 is
satisfied by literal text plus three distinct shapes, and a rebrand would exceed this task's
brief. A test asserts no fourth class accent can be introduced.

## 8. Limitations — stated plainly

- **Neither border token meets the 3:1 non-text floor.** `--border` is **1.43:1** on `--surface`
  (1.26:1 on `--canvas`) and `--border-strong` is **1.80:1** (1.58:1 on canvas). Both are kept at
  the shipped values because they render as decorative dividers, not as the sole carrier of
  state, and restyling them would be a visual redesign. But this is a **real, unaddressed gap**:
  any future control that relies on a border alone to convey state would fail 1.4.11. I am not
  claiming these pass.
- **The type size is unchanged.** Body stays 14px and labels 12px, i.e. exactly at the
  contract's stated minimums. Several sub-12px sizes (10px, 11px) still exist in the
  professional layer; the contract sets a target, and I did not widen the brief to restyle them.
- **`mypy` does not cover this task** — it is scoped to `app/g6/backend/osteopatch`. TypeScript
  is covered by `tsc -b`.
- **The 28 new tests are not in CI's blocking set.** Wiring them in needs Makefile/CI edits this
  task is not authorised to make.
- **`?raw`/`?inline`/`import.meta.glob` all return empty under `css: false`.** Any future test
  that wants real stylesheet content must read from disk, and will hit the same `@types/node`
  wall.
- Real Grad-CAM heatmaps remain unverified (torch absent); the 503 observed in the sweep is the
  documented honest refusal, not a regression.
- AWS, deployment, and the original G4 bundle were untouched and unauthorised.
