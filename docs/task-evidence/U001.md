# U001 — Stable navigation, deep links, and browser history

**Status:** IMPLEMENTED_VERIFIED · **Acceptance:** NOT_REVIEWED (this is the implementer's receipt, not an acceptance)
**Branch/worktree:** `feat/prompt-pack-run` in `wt/pack` · **Baseline:** `626aaad` (origin/main, unchanged — nothing committed)

## 1. What was actually true before this task

Measured, not assumed. `App.tsx` held the current screen in a `useState<View>` union of
`workbench | patch | model-card | attribution`. There was no URL anywhere in the app: no
`location`, no history, no deep link, no Back button in the browser's sense. `PatchReview`'s
"Back to workbench" was a state call. A reload always landed on the workbench regardless of
where you were, and a link to a patch could not be pasted at all.

So the brief's "Baseline stance: New or partially available" is accurate, and
`NO_CHANGE_VERIFIED` was not available for this task. The one thing that *did* already work
and was preserved is the ability to open a patch and return from it — Step 01's requirement —
and every existing `data-testid` in the tree is still present and unchanged (verified by the
98-test suite, which includes the pre-existing 89).

## 2. What was built

Three task-owned files plus one declared integration hook (see §5 for the hook).

**`app/g6/frontend/src/navigation.ts` (new, 147 lines, no React).** A typed route union
`workbench{context} | patch{imageId, context} | model-card | attribution |
not-available{requested, declared}`, hash parse/serialize, query validation, and a single
`hashchange` subscription that returns its own unsubscribe. Hash routing was chosen because
the app is served as static files: no router dependency was added, and the installed
`package.json` (React 18 + Vite + vitest) is untouched.

**`app/g6/frontend/src/App.tsx`.** The location became the source of truth. `currentRoute()`
seeds the initial state, so a deep link works on first paint; one `hashchange` listener
applies Back/Forward and is removed on unmount. `go(route, { replace })` pushes for
navigation and *replaces* for context-only edits, so typing in the search box does not fill
the history with a step per keystroke.

**`app/g6/frontend/src/test/navigation.test.tsx` (new, 9 tests).** U001-AT01..AT05, plus the
route module's own table-driven cases.

Step 07 asked for a capability-aware nav rather than a menu of inert buttons. Only the three
implemented destinations are rendered, from `NAV_ITEMS`; the five declared-but-unimplemented
routes in the brief's union (`overview`, `source-groups`, `analytics`, `system`, `demo`) are
reachable by deep link but never listed, and they show a not-available view rather than
pretending. Step 08's current-page indicator is a real `aria-current="page"` (exactly one
element carries it, asserted), and the skip link is the first tab stop, asserted in Chromium.

## 3. The integration hook, declared

`Workbench.tsx` is **not** in the brief's section 5 allowed surface, and it is the one place
this task had to reach outside its own files. Its `filter`, `sort`, `q` and `page` lived in
local `useState` with no prop in or out, so *U001-AT01 — "restores the same image ID **and
queue context**"* — and the section 11 rehearsal ("return to the original filtered
workbench") are simply unreachable without it. Shipping a URL that says `?filter=reviewed`
while the control shows `all` would have been a feature that visibly lies.

The hook is two **optional** props, `context` and `onContextChange`, plus moving `SORTS` and
`FILTERS` into `navigation.ts` so the URL validator and the rendered `<option>` values come
from one source instead of two that can drift. Callers passing only `onOpen` are unaffected
and the two pre-existing `Workbench` tests pass untouched. No other worker owns the file: it
was unmodified since the baseline commit. The brief's "list that hook in the receipt"
instruction is why it appears in `changed_files` and in `required_approval`.

## 4. Red first, and three real defects the process caught

Acceptance tests were written before any implementation. The first red run was 9 failures for
the intended reasons: the five module tests failed on `Failed to load url ../navigation` (the
module does not exist yet) and the four App tests failed *behaviourally* — the app ignored the
URL, so no patch rendered from a deep link and no not-available view existed. Getting the
App-level tests to fail that way needed an opaque dynamic-import specifier, because Vite
resolves a literal one at transform time and would have failed the whole file before any test
could run.

Two of my own test bugs were fixed rather than worked around: I had written the *invalid*
input as the expected value in the validation table, and I had listed `workbench` among the
declared-but-unavailable routes even though it is implemented.

**A real defect the tests surfaced.** The first implementation depended on `onContextChange`
inside a `useEffect`. The caller re-creates that callback on every render, so the effect
re-ran forever: `setRoute` → render → new callback → effect. It did not fail a test; it hung
the run, and a vitest worker ballooned to 1.3 GB before the 600 s timeout. The fix reads the
callback through a ref and depends only on the context values. Without the discipline of
watching what a command actually prints, this would have shipped as "the test runner is
flaky".

**A measurement error of my own.** U001-AT02 asserts one screen change per history step. It
first failed with 3 fetches where 2 were expected. The extra call had no `q` key, which
identified it as `PatchReview`'s own `listImages({sort, filter, page, page_size})` on mount —
it builds the prev/next queue. The assertion was counting two screens' fetches as one. The
test now counts workbench-shaped fetches and says why in a comment.

## 5. Boundary sweep, outside the test harness

`navigation.ts` was compiled with esbuild and driven directly by Node, over 19 hostile
inputs: emoji, a 500-character id, percent-encoded traversal, duplicate and out-of-range
`page` keys, `__proto__`/`constructor` in the query, control characters, a 5,000-character
search term, a 300-segment path, and case-mismatched route names. **0 throws, 0 unstable
parse/serialize round trips.** Confirmed directly: no prototype pollution, search text capped
at 200, control characters stripped, unknown keys ignored, and `page=1e308` / `Infinity` /
`1.5` / `0` / `-3` / duplicates all falling back to 1.

One consequence of this feature deserves the check rather than the assumption: a URL can now
carry an *arbitrary* image id, where before ids only ever came from the server. So
`api.ts`'s path construction was read — `getImage` and every sibling build their path with
`encodeURIComponent(imageId)`, so a traversal-shaped id such as `../../etc/passwd` is inert.

## 6. Security: only navigation context can reach the URL

`serializeRoute` builds its string from four named fields. There is no pass-through of
unknown query parameters, so a token, patient identifier or review note has no code path into
the location. U001-AT05 proves it from both ends: typing `dx: invasive carcinoma, block A3`
into the review note and navigating leaves no trace in the href, and a test smuggles `token`,
`review_note` and `patient_id` onto a route object and asserts none appears in the hash.

## 9. Limitations and what I did not do

- **The skip link has no visual treatment.** It is a real focusable control that moves focus
  to `<main id="main-content">`, but hiding it until focused needs one rule in
  `app/g6/frontend/src/styles.css`, which is outside the allowed surface. Flagged, not
  worked around.
- **`PatchReview` ignores the queue context** for its prev/next queue: it calls
  `listImages({sort: "priority", filter: "all", page: 1})` with hardcoded values. Pre-existing
  behavior, unchanged, left alone because fixing it would alter patch navigation.
- **Search text travels in the URL.** That is what step 3 asks for ("keep filter/sort/page/
  search context in validated query parameters"), capped at 200 characters with control
  characters stripped. It is not a reviewer note or a patient identifier — but if search terms
  must not appear in a pasted link, that is a product decision for the integrator, not one I
  should make silently.
- **The five unimplemented routes are reachable but not listed**, and show a not-available
  view. They are declared routes, not typos, and the view says which.
- **Nothing is committed**, so the whole evidence base — including this receipt and its gate
  records — remains untracked, and `scripts/check_repository.py` will report these citations
  as missing on a fresh clone. That is the honest cost of the no-commit instruction, not a
  defect in the check.
