## What was actually wrong before this task

`Workbench.tsx` held read state as three independent booleans — `data`, `loading`, `failed`. That
shape cannot express four of the situations the task asks for, and the consequences were real:

1. **The previous query's cards were presented as the current query's results.** While a new query
   loaded, the skeleton and the *old* cards were on screen together (`Workbench.tsx:122` rendered the
   skeleton, `:140` still mapped `data.items`). Nothing said those cards belonged to a different query.
2. **A failed refresh threw the reviewer's context away.** `setData(null)` on error, so a reviewer who
   lost connectivity mid-session lost the page they were working through.
3. **A 403 offered "Try again".** The error box rendered the same retry button for every failure
   including a permission denial.
4. **Nothing was announced.** Only `role="alert"` on the error box. Loading, ready and empty changes
   were silent to a screen reader.
5. **Requests were never aborted** — just ignored via a boolean `active` — and `reloadKey` retries
   were unbounded and could stack.
6. **No browser-test handle**: a test could only guess when loading finished.

## What was built

[AsyncState.tsx](../../app/g6/frontend/src/components/AsyncState.tsx) (new, 278 lines) holds §6's
contract as one discriminated union — `idle | loading | refreshing{data} | ready{data} |
empty{reason,data} | failed{error} | offline{error,data}` — the pure transitions between them, and
`AsyncStatus`, which renders them. [Workbench.tsx](../../app/g6/frontend/src/components/Workbench.tsx)
(207 lines) now holds one `AsyncState<ImageList>`, passes an `AbortSignal`, and publishes
`data-async-state`.

Two boundaries were respected and are worth stating plainly:

- **No new CSS.** `inline-error`, `empty-state`, `gallery-skeleton`, `muted`, `small` all already
  exist. Nothing was added to `styles.css`, so U002's earth-tone direction is untouched.
- **Nothing outside §5's surface.** `strings.ts` still carries `workbench.loadError`,
  `workbench.empty`, `workbench.emptyHint` and `common.retry`, now unused, because removing them
  would have meant editing a file this task does not own. They are dead entries for the integrator.

## Two real defects the process caught

1. **`run_gate.py` silently loses a gate's entire output** on this host. `subprocess(text=True)`
   decodes as cp1252; vitest emitted a byte that failed, the reader thread died, and the record came
   back with no output at all — an evidence record with no evidence. Worked around per-invocation with
   `PYTHONUTF8=1` (UTF-8 mode changes text I/O decoding even though `locale.getencoding()` still
   reports cp1252). Not fixed inside U003: `run_gate.py` is not this task's file.
   **RESOLVED 2026-10-05, after U003:** `run_gate.py` now captures bytes and decodes them
   itself, so `PYTHONUTF8=1` is **no longer needed and must not be carried forward**. That
   fix also found the old path silently *corrupted* output whenever the bytes happened to be
   cp1252-decodable — see `record_note` in
   [u001-rehearsal.json](../evidence/gates/u001-rehearsal.json).
2. **A 500 and a 403 were announced to the reviewer as "Offline."** The §11 rehearsal's 500 check
   failed on this. The stale banner said `Offline` unconditionally, so a server that answered with an
   error was reported as a dropped connection. Fixed at the cause (`isOffline`/`staleTitle`), and a
   fourth AT03 test now pins that only `code === "network"` is offline.

The build gate also caught an unused `ReactNode` import that the test suite did not.
