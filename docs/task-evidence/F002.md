# F002 — deterministic review fixture

**Generated:** 2026-10-05 · **Branch:** `feat/prompt-pack-run` · **HEAD:** `626aaadc9e4282b470b74fe94893a412cf7d127a`

> **Educational research prototype only. Not for diagnosis, treatment decisions, or predicting

This fixture builds the pack's hand-check example as a real, throwaway SQLite database. Its
numbers are **test values**. They are not production statistics, not model accuracy, and not a
claim about tissue.

---

## 1. What was built

`app/g6/backend/tests/fixtures/review_fixture.py` — `make_review_fixture(root, variant)` returns
`FixturePaths{root, db_path, image_root, expected_snapshot_path, variant}` and starts no
application. Seven variants: `default`, `no_reviews`, `no_predictions`, `empty`, `corrupt_asset`,
`empty_project`, `two_models`.

**Reuse, not a parallel schema (task Step 01).** The schema comes from
`osteopatch.db.run_migrations`; rows are written through `osteopatch.repo.upsert_prediction` and
`repo.submit_review` — the same constructors production uses. This module issues no `CREATE
TABLE`. Review status reuses `repo._review_status` rather than re-deriving the mapping.

The fixture model identity is deliberately **not** the frozen production hash. Nothing produced
here can be mistaken for `baseline-frozen-g4` evidence.

## 2. The hand-check example

Eight images in two source groups, one prediction each under the selected model:

| Image | Group | Predicted | Latest action | Status |
|---|---|---|---|---|
| fx-01 | A | NON_TUMOR | ACCEPT (rev 2, superseding a DEFER at rev 1) | reviewed |
| fx-02 | A | NON_TUMOR | ACCEPT | reviewed |
| fx-03 | A | VIABLE_TUMOR | CORRECT -> NECROSIS | reviewed |
| fx-04 | A | NECROSIS | DEFER | deferred |
| fx-05 | B | NECROSIS | DEFER | deferred |
| fx-06..fx-08 | B | various | — | unreviewed |

Measured by the rehearsal run (not copied from the contract):

```
COUNTS: total_images=8 prediction_images=8 predictionless_images=0
        unreviewed_images=3 decided_images=3 deferred_images=2 touched_images=5
        accepted_images=2 corrected_images=1 disagreement_images=1 qc_flagged_images=0
  RATE correction_action_rate  1/3      RATE defer_fraction       2/5
  RATE review_completion       3/8      RATE reviewer_agreement    2/3
PER-IMAGE: fx-01:reviewed fx-02:reviewed fx-03:reviewed fx-04:deferred
           fx-05:deferred fx-06:unreviewed fx-07:unreviewed fx-08:unreviewed
```

These match the contract's expected values. The check is not circular: `EXPECTED_DEFAULT` holds
hand-written literals, while the manifest is derived from `counts_from` querying the seeded
database.

### Domain semantics honoured

- Canonical classes remain exactly `NON_TUMOR, VIABLE_TUMOR, NECROSIS`; `MIXED_*`, deferred, and
  poor-quality stay metadata. No fourth model output exists anywhere in the fixture.
- `ACCEPT` resolves to the predicted class of that event's `prediction_id`, so an accept can
  never register as a disagreement.
- `CORRECT` resolves to `selected_class`; fx-03's target genuinely differs, which is the single
  disagreement.
- Reviews are append-only. `add_superseded_event` only ever `INSERT`s beneath the latest revision.
- A review bound to **another model's** prediction does not decide the selected model; fx-06 stays
  unreviewed in the selected-model view (AT03).
- Rates with no denominator return `value: null` plus an `unavailable_reason`, never a bare `0.0`.

## 4. Boundary cases exercised

No rows (`empty`) · zero reviews (`no_reviews`) · predictionless images stay visible but leave
agreement denominators (`no_predictions`) · unavailable artifact (`corrupt_asset` writes a
deliberately undecodable `TEST_FIXTURE` asset and raises a warning) · unauthorized/empty project
(`empty_project`) · changed model (`two_models`) · duplicate retry under one idempotency key
(appends exactly once) · unknown `prediction_id` raises `NotFoundError` · accept-equals-predict is
not a disagreement · config default DB path is never created.

## 5. Test-first evidence

**One test of mine was wrong and was corrected before implementing.** I had asserted the

stricter, contract-accurate version and a separate `empty` variant was added for the true no-rows
case. This is recorded rather than quietly fixed.

## 8. Defect found in this task's own code

A completion check found a real counting bug that the 30 original tests missed.
`counts_from()` seeded `prediction_images` from the image total when no model was
selected, then counted matching images again, so the `two_models` fixture reported
**16 predictions for 8 images**:

```
selected model : 8 8 0
model=None     : 8 16 0     <-- prediction_images > total_images
```

Fixed at the cause: `prediction_images` is now an image count in both selection modes,
with `predictionless = total - prediction_images`. Locked by
`test_boundary_counts_are_images_not_prediction_rows`, which asserts
`prediction_images <= total_images` for both a selected model and `model=None`.
No assertion was weakened to make it pass; the suite grew from 30 to 31 tests.

- `mypy` is scoped to `app/g6/backend/osteopatch`, so these test files are not type-checked.
- Task verification command 1 exits 5, not 0. The command is correct as written but targets a
  module with no tests; the equivalent import-and-build check is recorded above.
- Real H&E, the original G4 bundle, torch-backed attribution, and any cloud resource remain
  untouched and unexercised.
